# SEO QA Design System

## Overview

SEO QA는 내부 사용자가 Shopify 사이트 점검을 반복 실행하고 결과를 빠르게 판독하는 작업형 대시보드입니다. 디자인은 마케팅 랜딩 페이지가 아니라 운영 도구에 맞춰 조용하고 밀도 있게 구성합니다.

## Layout

- 기본 화면은 `1020px` 안팎의 중앙 정렬 래퍼를 사용합니다.
- 홈은 신규 점검 설정 패널과 이전 점검 히스토리 패널을 나란히 배치합니다.
- 상세 화면은 요약 지표, 대시보드 메타, 페이지별 결과 테이블, 에러 상태, 실행 기록 순서로 구성합니다.
- 페이지 상세는 점수 요약, URL 상태, 추출 SEO 값, 항목별 판정 순서로 구성합니다.

## Typography

- 기본 폰트는 시스템 sans-serif를 사용합니다.
- H1은 화면 목적을 드러내는 짧은 제목으로 둡니다.
- 패널 제목은 기능명을 명확히 적습니다.
- 테이블과 메타 정보는 스캔이 쉬운 작은 크기와 충분한 줄 간격을 사용합니다.

## Components

- Topbar: 화면 제목, 보조 액션, 새로고침/목록 버튼을 배치합니다.
- Panel: 주요 기능 단위의 흰색 표면입니다.
- Metric Card: 평균 점수, 통과, 미통과, 에러 수를 표시합니다.
- Table: 페이지별 URL, 상태, 점수, 통과/미통과, Title을 보여줍니다.
- Detail Card: 에러 또는 미통과 항목을 접고 펼칠 수 있게 표시합니다.
- Dialog: 인증 정보 입력용으로 사용하되 저장하지 않는다는 안내를 포함합니다.
- Status Chip: `completed`, `running`, `failed`, `passed`, `error` 상태를 색상으로 구분합니다.

## Interaction

- URL 입력은 필수입니다.
- 최대 페이지 수는 `1~100` 범위입니다.
- robots.txt 준수 여부는 체크박스로 제어합니다.
- 인증 필요 체크 시 다이얼로그를 열지만 인증 정보는 서버에 저장하지 않습니다.
- 이전 점검은 재검증 설정으로 다시 불러올 수 있습니다.
- 점검 상세의 페이지 URL 클릭 시 페이지 상세로 이동합니다.

## Do's

- 데이터 판독이 빠른 테이블과 요약 지표를 우선합니다.
- 에러 원인과 미통과 이유는 URL 옆에서 바로 확인 가능하게 둡니다.
- 보안/정책 관련 안내는 짧고 명확하게 씁니다.
- 버튼, 입력, 패널 반경과 간격은 일관되게 유지합니다.

## Don'ts

- 장식용 그래픽이나 큰 히어로 영역을 추가하지 않습니다.
- 결과 테이블을 카드 목록으로 과도하게 분해하지 않습니다.
- 인증 정보 저장을 암시하는 UI 문구를 쓰지 않습니다.
- 내부 점검 도구에 맞지 않는 과한 브랜드/마케팅 톤을 쓰지 않습니다.
